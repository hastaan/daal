# Embedded Bootstrap Material v1

## Status

Locked at the end of Phase 1D.

## Purpose

This spec freezes the on-disk layout of the embedded bootstrap material
(Tier-1 + Tier-2). The embedded layout is the explicit hand-off point
between the operator's signing process (today: `daal-publish` against
test fixtures; from V1.7: operator HSM-backed keys) and the client
build.

## Layout

```
core/bootstrap/embedded/
  embedded.go                    Go loader. Uses go:embed.
  fixtures/
    project-root.pub             Ed25519 32-byte pubkey (PEM).
    publisher-0.pub              Ed25519 32-byte pubkey (PEM).
    publisher-1.pub              Ed25519 32-byte pubkey (PEM).
    publisher-display.json       fingerprint_hex → human-readable name.
    pointers-primary.json        signed by project-root.
    pointers-fallback.json       signed by project-root.
    tier2-seed-0.sbp             signed by publisher-N.
    tier2-seed-1.sbp             signed by publisher-N.
    tier2-seed-2.sbp             signed by publisher-N.
```

Every file under `fixtures/` is **public material**. The corresponding
private keys live ONLY in the operator's keystore (`daal-publish` per
`publisher-cli-v1.md`); they MUST NOT enter the build artifact, the git
tree, or any CI workspace beyond the dedicated signing host.

## Generation

A repo-internal helper at `core/bootstrap/internal/cmd/genembedded`
produces a fresh placeholder set:

```
go run daal/core/bootstrap/internal/cmd/genembedded \
  ./core/bootstrap/embedded/fixtures
```

The helper exists so tests have a usable artifact and the V1.7 swap
target. Production-grade material is generated by `daal-publish` and
substituted into `fixtures/` by the operator before tagging the release.

## Trust rules

- The project root pubkey MUST be present and parse as 32-byte Ed25519.
- At least one publisher pubkey MUST be present.
- Both pointer sets MUST verify under the project root.
- Each Tier-2 seed MUST be signed by a publisher whose pubkey is in the
  embedded set (compile-time test in `embedded_test.go`).
- Each Tier-2 seed MUST satisfy `valid_until - created_at ≤ 30d`
  (compile-time test).

## Rotation

| Material | Rotation event |
|---|---|
| Project root | New release line; rare. |
| Publisher pubkey | New publisher, retiring publisher, or compromised key. |
| Pointer sets | New release; signed by project root each time. (V1.5.5: hot rotation.) |
| Tier-2 seeds | Every release; older seeds expire and are silently retired. |

The release-engineering process is documented out-of-band; this spec
fixes the file shape only.

## Privacy

- The embedded material is the same for every user; downloading the APK
  reveals no per-user information.
- The project root pubkey is the only fixed piece of cryptographic
  material that ties one release to another. The publisher set may
  change every release.
- Old releases continue to verify pointer sets they shipped with;
  forwards-incompatibility is intentional, since adversaries cannot
  unpublish a binary already on a user's device.

## OPSEC tests

- `core/bootstrap/embedded/embedded_test.go` asserts:
  - LoadManifest succeeds.
  - PrimaryPointers and FallbackPointers verify under the embedded
    project root.
  - Each Tier-2 seed's `valid_until - created_at ≤ 30d`.
  - Each Tier-2 seed's publisher is in the embedded set.
  - Each pointer's `expected_publisher_fingerprint_hex` references a
    publisher in the embedded set.
- `core/bootstrap` source-grep test forbids `net/http`, `0.0.0.0`,
  `[::]`, `*` listen literals.
