# Phase 1D — Bootstrap Directory and Embedded Seed Material — Handover

## Status

**Complete.** Engine ABI 23 → 26 (3 new functions, append-only).
`engine_version` unchanged at `daal-core 0.3.0+offline-sharing` — Phase
1D is purely additive on the surface and the routestore schema. The
version bumps when V1.5 ships.

## What lands in this phase

- **Tier-1/2/3 bootstrap model** per the V1.5 roadmap, locked by four
  new specs:
  - `specs/bootstrap-pointer-v1.md`
  - `specs/bootstrap-directory-v1.md`
  - `specs/bootstrap-tiers-v1.md`
  - `specs/embedded-material-v1.md`
- A **new core package** `core/bootstrap` with:
  - signed pointer-set parser/verifier (project-root signed),
  - raw-TLS HTTP/1.1 fetcher (no `net/http` in core),
  - SOCKS5 tunnel-dialer adapter (hand-rolled, no `golang.org/x/net/proxy`),
  - bootstrap orchestrator (PinTier1 → InstallSeeds → Refresh → Status),
  - Tier-2 demotion and Tier-3 import routing,
  - emergency-pool labeling helpers.
- A **new embedded sub-package** `core/bootstrap/embedded` that
  `go:embed`s the Tier-1 (project root pubkey + 2 publisher pubkeys +
  signed primary/fallback pointer sets) and Tier-2 (3 short-lived
  `.sbp` seeds) material baked into every build.
- A **fixture generator** at
  `core/bootstrap/internal/cmd/genembedded` that produces a
  reproducible-by-process placeholder material set; tests use it; the
  V1.7 first-publisher pilot replaces the placeholder material with
  operator-signed keys without changing the file shape.
- **3 new engine ABI functions** (cshared + gomobile):
  `engine_bootstrap_install_seeds`, `engine_bootstrap_refresh`,
  `engine_bootstrap_status`.
- **CLI surface** in `cmd/daal-core`: `bootstrap-install`,
  `bootstrap-refresh`, `bootstrap-status`.
- **Compose UI**: `BootstrapScreen.kt` (welcome / refresh / blocked
  modal), `EmergencyBadge.kt` (persistent red pill while connected via
  emergency). EN + FA strings.
- **OPSEC tests** extended: `TestBootstrapNoNetHTTP` enforces no
  `net/http`, no `0.0.0.0`, no `[::]` listen literals inside
  `core/bootstrap`.
- **Importer trust path:** unchanged. We pre-pin Tier-1 publishers via
  the existing `SaveImport` / `UpsertPublisher` flow so a directory
  `.sbp` whose publisher matches a Tier-1 pin takes the existing
  silent-import branch. No new TrustOverride hook was needed.
- **Routestore schema:** unchanged. `UpsertRoute`'s SQL UPDATE clause
  was extended to honor `source_type` and `user_note` on conflict (this
  was a pre-existing oversight; Phase 1D needs both). The fix is a
  one-line SQL change with no data migration.

## Architectural decisions captured

1. **No `net/http` in core, ever.** Phase 1D introduced the first
   network-facing fetch and chose pure raw-TLS + hand-rolled HTTP/1.1.
   The rule from Phase 1C (`core/share` does not use `net/http`) now
   has a partner rule for `core/bootstrap`. `TestBootstrapNoNetHTTP`
   makes it permanent.
2. **Tier-3 directory format = signed `.sbp` with `bundle.type =
   "directory"`.** No new format, no new signature path, no new
   importer code path. The `bundle_cmd.go` enum was extended to include
   `"directory"`. The trust-prompt suppression is achieved by pre-
   pinning Tier-1 publisher fingerprints, which routes the import
   through the existing "publisher already trusted" branch.
3. **Pointer rotation deferred to V1.5.5.** This phase ships static
   primary + fallback pointer sets only. The pointer-set rotation
   envelope (project-root-signed re-issuance consumed at runtime) is a
   small follow-up; the schema is already in place.
4. **Emergency budget = data-model + UI label only.** Real per-route
   `bytes_used_today` enforcement (100 MB warn / 200 MB pause/day) lands
   in V2's route-budget engine. V1.5 ships the persistent "Limited
   capacity" red pill on every emergency-class connection.
5. **Tunnel-dialer is wired but not yet routed through sing-box.** The
   `TunnelDialer{SocksAddress: ""}` form falls through to
   `NewDirectDialer`; the engine's SOCKS5 inlet is not yet exposed in
   the V1 build. The hookup point is one config change in the engine
   driver and is reserved for V1.5.5.
6. **The fixture generator is checked in.** Tests, embedded artifact,
   and the V1.7 swap target all use the same generator. The V1.7 pilot
   replaces the file contents under `core/bootstrap/embedded/fixtures/`
   with operator-signed material; the file shape is identical.

## Known limitations / follow-ups

1. **Tunnel-aware fetch** — currently always direct. Wire `TunnelDialer`
   to the engine's SOCKS5 inlet when the driver is connected. (V1.5.5)
2. **Pointer rotation** — signed pointer-set rotation envelope to update
   the embedded primary/fallback at runtime without an app update. (V1.5.5)
3. **Onion / IPFS pointers** — fetcher accepts only `https://` in
   Phase 1D. `.onion` and `ipfs://` handlers are V1.5 / V1.5.5.
4. **Real Tier-1 keys** — placeholder material substituted with
   operator-signed keys before the V1.7 first-publisher pilot. The
   substitution is a directory-level swap; no code change required.
5. **Real budget enforcement** — V2.1 route-budget engine.
6. **Directory bundle lints** — the `DIRECTORY_*` lint codes from
   `bootstrap-directory-v1.md` are documented but not yet implemented in
   `bundle/go/publisher/lint.go`. `daal-publish` will need a follow-up
   PR to fail-loud when an operator builds a directory bundle that
   violates expiry or scarcity rules.
